# 2026-08-20 — `v0.1.2` apply refused at the secret gate

**Status:** closed on the audit question. The apply is still undone; the fleet
runs `v0.1.0`.
**Impact:** none to the running fleet. No service was restarted, no release
directory was written, and no alert was missed. The deploy simply did not
happen, twice.

Written up on 2026-09-21, a month late, because the audit log appeared to be
misreporting its own safety mechanism and that needed either confirming or
disproving before anything else could be deployed.

## What the record showed

```
2026-08-20T19:53:02Z  apply     clinical-trials  failed   v0.1.0 -> v0.1.2  (ubuntu, 3.504s)
2026-08-20T19:53:04Z  rollback  clinical-trials  failed   v0.1.2 -> v0.1.0  (ubuntu, 2.055s)
2026-08-20T19:55:22Z  apply     clinical-trials  failed   v0.1.0 -> v0.1.2  (ubuntu, 1.508s)
2026-08-20T19:55:24Z  rollback  clinical-trials  failed   v0.1.2 -> v0.1.0  (ubuntu, 1.51s)
```

Two applies, each followed by a rollback, all four `failed`. Yet
`clinical-trials` was `active` and healthy at `v0.1.0` — precisely the ref the
rollbacks were restoring. A rollback recorded as failed, to a ref the service is
demonstrably sitting on, suggests the field that reports whether recovery worked
cannot be trusted. Since that field is what would report on the safety of any
future deploy, this blocked deploying at all.

## What actually happened

`applyService` resolves secrets before it does anything else:

```go
secrets, err := a.Resolver.Resolve(sp.SecretNames)
if err != nil {
    return fmt.Errorf("resolve secrets: %w", err)
}
```

Resolution failed — reported at the time as the instance having no IAM role, so
`ssm:GetParameter` was denied. The apply therefore returned before its first
mutating step: no clone, no virtualenv, no unit written, no restart.

`rollbackTo` is not a separate code path. It rebuilds the `ServicePlan` with the
previous ref as the target and calls the same `applyService`, which called the
same resolver, which failed the same way. The rollback also returned before
mutating anything.

So the service stayed on `v0.1.0` throughout — not because the rollback restored
it, but because nothing ever moved it. Both `failed` statuses were accurate. The
faulty step was the inference from "healthy at the previous ref" to "the rollback
must have worked".

Durations corroborate it: 3.5s and 1.5s for the applies, about 2s and 1.5s for
the rollbacks. Cloning a tag and building a virtualenv does not finish in two
seconds.

## Resolution

No code defect. The audit log was correct and is trustworthy.

The behaviour is now pinned by
`internal/engine/secretgate_test.go`, which drives a refusing resolver through a
real `Apply` and asserts three things: the resolver is called twice (forward, then
rollback), both audit entries read `failed`, and no mutating command is issued on
either pass. Removing the gate's `return` makes it fail.

That test also establishes something useful for the next deploy: **a
secret-resolution failure is safe.** If the gate is still broken, an apply
changes nothing and records two accurate `failed` entries. The cost of trying is
a no-op.

## Still open

Whether secret resolution works now. The instance has an IAM role today, which
is the blocker that was reported, but nothing has re-tested the gate. This is not
assumed to be fixed; the next apply will establish it either way, safely.

## Contributing factors

- **The rollback shares the forward path.** That is a deliberate and good
  design — the previous spec fully determines the previous code — but it means a
  pre-flight failure fails the rollback identically, and a reader who expects
  rollback to be a recovery routine is surprised.
- **A rollback that never began looks like a rollback that failed.** Both are
  `failed`. Distinguishing "refused before acting" from "acted and could not
  finish" would have made this readable in seconds rather than a month.
  Worth considering: a `refused` outcome, or a `mutated: false` detail field.
- **Nothing was deployed for a month** and the audit log sat unread until the
  read path existed.
